# DEF-002 · P1 · Отказа «нет данных» не существует: ниже порога всё равно отдаётся top-5

Проект: bot_for_legal_consultations
Дата: 2026-10-30
Источник находки: чтение кода
Статус: **исправлен**, проверено (см. «Закрытие»)

## Симптом

Ожидаемо: если ни один найденный фрагмент не прошёл порог релевантности
(0.3), система говорит «не нашёл» и не отвечает.

Фактически (по коду): после фильтрации по порогу есть fallback, который
возвращает top-5 при нулевом количестве прошедших:

    # rag_engine.py:1000-1005
    if not top_docs:
        log.warning("No documents above threshold, using fallback to top-5")
        top_docs = [doc for doc, score in ranked[:RERANK_TOP_K]]

Плюс в production-режиме reranker отключён (`_get_reranker()` возвращает None),
и тогда вообще не считается score:

    # rag_engine.py:968-971
    if reranker is None:
        top_docs = docs[:RERANK_TOP_K]

То есть на практике в прод-конфигурации порог не применяется никогда.

## Что это даёт на выходе

Вопрос «как приготовить борщ» получает пять случайных статей ГК, дальше LLM
строит по ним связный ответ. Пользователь видит юридическую консультацию,
к которой нет оснований. Для юридического бота это худший класс ошибки:
не «не ответил», а «ответил уверенно и мимо».

## Как воспроизвести

1. Спросить заведомо нерелевантное: «как приготовить борщ», «какая погода».
2. Ожидаемо: отказ.
3. Фактически: ответ с ссылками на статьи ГК.
4. В логах искать `No documents above threshold` — если строка есть, а ответ
   всё равно ушёл, дефект подтверждён.

## Предложение

- Вернуть честный отказ: `if not top_docs: return [], ""` до fallback.
- Ввести порог для семантического поиска отдельно (сейчас его нет: `docs[:5]`
  без отсечения по score).
- Завести эталонный кейс L-101 в прогон, чтобы регрессия ловилась автоматически.

## Закрытие (2026-10-30)

Сделано не по предложенному выше плану, а иначе — и это важно.

Порог на score реранкера чинил бы только dev-режим: в production реранкера нет,
score не считается вообще, и порог не к чему прикладывать. Поэтому проверка
темы вынесена до поиска, отдельным шагом, который работает в любой конфигурации.

Добавлено в `rag_engine.py`:

    RELEVANCE_HARD_COSINE = 0.33   # лучший чанк совсем далёк — отказ
    RELEVANCE_SOFT_COSINE = 0.45   # чанк средний ...
    RELEVANCE_MIN_COVERAGE = 0.34  # ... и ни одного слова вопроса в тексте — отказ
    LegalRAG.check_topic_relevance(question)
    LegalRAG.OTHER_BRANCH_MARKERS / CIVIL_MARKERS

Пороги измерены, а не выбраны на глаз (`tools/qa_threshold_rules.py`,
20 своих вопросов и 12 посторонних):

    свои вопросы:  лучший косинус 0.376 … 0.719, покрытие слов 0.5 … 1.0
    чужие вопросы: лучший косинус 0.177 … 0.440, покрытие 0 … 0.5

Один порог по косинусу разделяет плохо (0.376 у «сервитута» против 0.440
у «дела Иванова»), поэтому правило из двух условий: жёсткий отказ при 0.33,
а в середине — по наличию слов вопроса в найденных текстах.

Отдельно — вопросы из других отраслей права: «какое наказание за кражу» имеет
косинус 0.51, то есть ближе, чем половина своих вопросов. Такие вопросы
отбиваются по маркерам отрасли («наказание», «уголовн», «лишение свободы»,
«административн»…), но только если в вопросе нет гражданских маркеров
(«взыскать», «ущерб», «возместить», «договор»…): «как взыскать ущерб от кражи» —
это ГК, и на него бот отвечает.
