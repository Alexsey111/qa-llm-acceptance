## Симптом

README в разделе тестов перечисляет:

    tests/test_security.py
    tests/test_database.py
    tests/test_rag_engine.py
    tests/test_sql_logger.py

Фактически в репозитории лежат:

    tests/test_article_lookup_simple.py
    tests/test_gk_structure_simple.py
    tests/test_security_simple.py

То есть тестов на базу и на RAG-движок нет, а заявлены оба.

## Почему это дефект, а не придирка

Именно в непокрытом месте и лежат DEF-001 (нет return) и DEF-002 (нет отказа).
Любой тест вида «вызвать retrieve_documents на общем вопросе и проверить,
что вернулся кортеж из двух элементов» упал бы на первом запуске. Отсутствие
теста — не стилистика, а причина, по которой P0 дожил до сдачи.

## Как воспроизвести

1. `grep -n "test_" tests/README.md` и `ls tests/` — сравнить списки.
2. `pytest --collect-only -q` — посчитать фактическое число тестов.
3. Ожидаемо: число тестов совпадает с заявленным и включает RAG.

## Предложение

- Либо дописать тесты (минимально: возвращаемый тип, отказ при пустом
  результате, отклонение выдуманной статьи), либо убрать список из README.
- В приёмке считать «документация расходится с фактом» отдельным дефектом:
  по README нельзя судить о готовности.

## Что не сделано

README проекта по-прежнему перечисляет `test_security.py`, `test_database.py`,
`test_rag_engine.py`, `test_sql_logger.py` — этих файлов нет. Правка README
не входит в приёмку: это решение владельца, что писать в документации.
Пока список не приведён к факту, дефект закрыт не полностью.

## Уточнение причины (2026-10-30, вечер)

При разборе оказалось, что дело было не в забывчивости автора, а в правиле
`.gitignore` на строке 228:

    # Тестовые скрипты
    test_*.py

Шаблон без ведущего слэша исключает файлы на любом уровне, в том числе
`tests/test_*.py`. То есть **ни один** тест никогда не попадал в репозиторий:
локально их было по крайней мере шесть, в Git — ноль. README перечислял файлы,
которые автор собирался держать рядом, а проверяющий видел репозиторий,
в котором тестов нет вовсе.

Исправлено:

    /test_*.py        шаблон ограничен корнем (черновики в корне по-прежнему скрыты)
    chroma_legal_db_old_model/   добавлен в ignore (55 МБ локального резерва)

После правки в репозиторий попали все тесты, включая десять файлов, написанных
в ходе приёмки; прогон на чистом клоне даёт 99 passed / 0 failed.

## Поправка к самой карточке

В первоначальной формулировке было сказано «фактически в репозитории лежат
`test_article_lookup_simple.py` и ещё два». Это неверно: они лежали **на диске**,
а в репозитории не было ни одного тестового файла. Список содержимого
репозитория берётся из `git ls-files`, а не из `ls`; приёмка сама нарушила
правило «сначала воспроизвести» — правка внесена, факт перепроверен через
`git ls-files tests`.
