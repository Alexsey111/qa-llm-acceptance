# DEF-009 · P2 · Проект не запускается вне Docker: пути в .env и словарь tiktoken из сети

Проект: bot_for_legal_consultations
Дата: 2026-10-30
Источник находки: попытка прямого прогона (`tools/qa_probe.py`)
Статус: открыт

## Симптом 1 — пути от контейнера

`.env` в корне содержит:

    DATABASE_URL=sqlite+aiosqlite:////data/legal_bot.db
    CHROMA_PERSIST_DIR=/data/chroma_legal_db

`/data/...` — путь внутри контейнера. На локальной машине база лежит в
`./chroma_legal_db` (55 МБ), но приложение смотрит в `/data` и падает:

    FileNotFoundError: ❌ Database not found at /data/chroma_legal_db
    Please run: python ingest_data.py first!

Сообщение об ошибке отправляет переиндексировать базу, хотя база есть — просто
не там. Это худший вид ошибки: она уводит в сторону.

## Симптом 2 — словарь токенизатора тянется из сети

После подстановки локального пути падение на инициализации:

    self.tokenizer = tiktoken.get_encoding("cl100k_base")
    requests.exceptions.ReadTimeout:
    HTTPSConnectionPool(host='openaipublic.blob.core.windows.net', port=443)

tiktoken скачивает BPE-словарь при первом использовании. Без доступа к этому
хосту (или без прогретого кеша `TIKTOKEN_CACHE_DIR`) приложение не стартует
вообще — ни в боте, ни в тестах.

## Почему это дефект, а не «особенность машины»

README описывает локальную установку как равноправную с Docker. Фактически
локальный сценарий не работает: сначала путь, потом сеть. Человек, который
пробует запустить проект без Docker, получает две ошибки подряд, обе не про
то, что реально надо сделать.

## Как воспроизвести

    cd bot_for_legal_consultations
    .venv/Scripts/python.exe tools/qa_probe.py
    # FileNotFoundError: /data/chroma_legal_db

    CHROMA_PERSIST_DIR=./chroma_legal_db .venv/Scripts/python.exe tools/qa_probe.py
    # ReadTimeout на openaipublic.blob.core.windows.net

## Предложение

- В `.env.example` держать локальные пути, а контейнерные — в `docker-compose.yml`
  через `environment:`.
- Ошибку «база не найдена» дополнить фактическим путём поиска и подсказкой
  про CHROMA_PERSIST_DIR.
- Прогревать кеш tiktoken на этапе сборки образа (`python -c "import tiktoken;
  tiktoken.get_encoding('cl100k_base')"` в Dockerfile) и описать
  `TIKTOKEN_CACHE_DIR` для офлайн-запуска.

## Частично закрыт (2026-10-30)

- Словарь tiktoken больше не нужен для эмбеддингов: `database.py` создаёт
  `OpenAIEmbeddings(check_embedding_ctx_length=False)`. Остался только счётчик
  длины контекста в `rag_engine` — он нужен лишь для оценки размера промпта
  и на поиск не влияет.
- После сборки индекса появилась самопроверка (`_verify_embeddings_alignment`),
  то есть «тихо испорченный индекс» больше не проходит как успешный (DEF-018).
- **Не закрыто:** контейнерные пути в `.env` (`/data/legal_bot.db`,
  `/data/chroma_legal_db`) — проект по-прежнему не запускается вне Docker
  без подмены переменных окружения.
