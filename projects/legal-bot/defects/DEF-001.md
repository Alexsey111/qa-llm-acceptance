# DEF-001 · P0 · Общий вопрос падает: функция поиска не возвращает результат

Проект: bot_for_legal_consultations
Дата: 2026-10-30
Источник находки: чтение кода, затем точечное воспроизведение
Статус: **исправлен и проверен повторно** (патч + tests/test_rag_contract.py)

## Воспроизведение (30.10.2026)

Точечный прогон с заглушками окружения — `bot_for_legal_consultations/tools/qa_probe_unit.py`:

    general            -> NoneType  контракт (docs, context): НЕТ
    specific_article   -> tuple     контракт (docs, context): ДА

То есть ветка общего вопроса действительно не возвращает значение, ветка
конкретной статьи работает. Полный прогон через `generate_answer()` в этом
окружении не удался раньше — см. DEF-009 (пути в .env от Docker, tiktoken
тянет словарь из сети).

## Масштаб (живой прогон 30.10.2026, 13 кейсов)

Через proxyapi (gpt-4o-mini), с обходом DEF-009: 7 из 13 кейсов прошли,
6 упали — все с этим же `TypeError`. Падают в том числе три негативных кейса
(«борщ», «кража», «дело Иванова»), где бот обязан был отказать. Побочно:
уточняющий вопрос (QueryClarifier) вызывается после поиска, поэтому до
исправления эта функция недостижима. Отчёт:
`qa-llm-acceptance/projects/legal-bot/runs/2026-10-30/run_report.md`.

## Симптом

Ожидаемо: любой вопрос, который не является запросом конкретной статьи,
попадает в ветку гибридного поиска и получает ответ.

Фактически (по коду): `LegalRAG.retrieve_documents()` в ветке `hybrid_rag`
не содержит `return`. Функция доходит до конца и возвращает `None`.

Вызов в `rag_engine.py:1255`:

    docs, context = self.retrieve_documents(question, query_type)

`None` нельзя распаковать в две переменные → `TypeError: cannot unpack
non-iterable NoneType object`. То есть падает каждый общий вопрос.

## Где

    rag_engine.py:901   def retrieve_documents(...)
    rag_engine.py:957-1005  ветка общего запроса (нет return)
    rag_engine.py:1255  распаковка результата

Ветки `article_range` и `specific_article` возвращают значения (строки 921, 954),
ветка `hybrid_rag` — нет.

## Как воспроизвести

1. Запустить бота, задать вопрос вне шаблона «статья N»:
   «что будет, если покупатель не оплатил товар?»
2. Ожидаемо: ответ по существу.
3. Фактически: ошибка обработчика (в логах — `error_handler`, пользователь
   видит сообщение об ошибке).

Альтернатива без бота: вызвать функцию напрямую и напечатать результат:

    from rag_engine import LegalRAG
    rag = LegalRAG()
    q = rag.enhanced_analyzer.analyze("что будет, если покупатель не оплатил товар?")
    print(rag.retrieve_documents("что будет, если покупатель не оплатил товар?", q))

Ожидаемо кортеж `(docs, context)`, фактически `None`.

## Почему это P0

Общий вопрос — основной сценарий бота. Из 40 проверок тест-плана 14 зависят
от этой ветки, то есть без исправления проверяется только четвёртая часть
функционала.

## Предложение

Добавить в конец ветки `hybrid_rag`:

    return top_docs, self._build_context(top_docs, query_type)

и тест на возвращаемый тип — первый тест, которого в репозитории нет
(существующие тесты покрывают структуру ГК, поиск по статьям и безопасность,
но не RAG-движок).
