## Симптом

    tests/test_rag_contract.py::test_general_returns_tuple
    AttributeError: 'NoneType' object has no attribute 'predict'
    rag_engine.py, retrieve_documents: scores = self._get_reranker().predict(...)

Тест подставляет `_get_reranker = lambda: None` и требует, чтобы поиск
в этом состоянии вернул кортеж `(docs, context)`. На текущем `main`
(коммит `60da60c`: CrossEncoder создаётся всегда, без флага PRODUCTION)
код падает.

## Почему это дефект, а не устаревший тест

Состояние «реранкера нет» — не выдумка теста. `_get_reranker()` создаёт
`CrossEncoder("cross-encoder/mmarco-mMiniLMv2-L12-H384-v1")` внутри запроса,
и веса тянутся из кэша HuggingFace или из сети. На этой машине кэш есть
(`~/.cache/huggingface`, 1.5 ГБ), но:

- в Docker-образе кэша нет, веса скачиваются при первом запросе;
- без доступа к huggingface.co (обычный случай без VPN) конструктор бросает
  исключение — и раньше это исключение вылетало из `retrieve_documents`,
  то есть **любой** общий вопрос превращался в ошибку вместо ответа;
- то же самое происходит при несовместимой версии `sentence-transformers`.

Отказ дорогого узла не должен уносить весь поиск: порядок слияния
(семантика + BM25) уже посчитан, реранк — улучшение сортировки, а не условие
работоспособности.

## Как воспроизвести (до исправления)

    cd "D:/python projects/bot_for_legal_consultations"
    .venv/Scripts/python.exe -m pytest tests/test_rag_contract.py -q
    # 1 failed: 'NoneType' object has no attribute 'predict'

## Исправление

`rag_engine.py`:

- `_get_reranker()` грузит модель в `try`, отказ запоминается флагом
  `_reranker_failed` (повторных попыток загрузки на каждый запрос нет),
  возвращается `None`;
- в `retrieve_documents` при `reranker is None` пишется предупреждение
  `reranker_unavailable_fallback` и отдаётся `docs[:RERANK_TOP_K]` — порядок
  слияния без реранка.
