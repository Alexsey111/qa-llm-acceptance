# DEF-018 · P2 · Сборка индекса зависит от словаря tiktoken и не проверяет результат

Проект: bot_for_legal_consultations
Дата: 2026-10-30
Источник находки: воспроизведение при переиндексации в приёмке
Статус: **исправлено**

## Симптом

`ingest_data.py` в окружении без доступа к `openaipublic.blob.core.windows.net`
падает на скачивании BPE-словаря. Если словарь подменить заглушкой (типичный
обход «чтобы запустилось»), сборка завершается успешно, пишет «✅ ЗАГРУЗКА
ЗАВЕРШЕНА УСПЕШНО» — и кладёт в индекс мусор:

    4937 документов, уникальных векторов 1266
    3671 чанк имеет вектор чужого документа
    косинус(сохранённый, пересчитанный по тому же тексту) = 0.02–0.05

## Причина

`OpenAIEmbeddings` по умолчанию (`check_embedding_ctx_length=True`) токенизирует
вход локально и отправляет в API последовательность токенов, а не текст.
Суррогатный токенизатор выдаёт для всех текстов одинаковой длины одинаковый
вход — модель честно возвращает одинаковые векторы. Ошибки нет ни на одном шаге.

Второй слой: результат сборки никем не проверяется. Ни `ingest_data.py`,
ни `database.py` не сверяют сохранённый вектор с текстом документа, поэтому
испорченный индекс неотличим от рабочего до первого содержательного вопроса.

## Почему P2, а не выше

В целевой конфигурации (Docker + интернет) словарь скачивается и всё работает.
Проблема проявляется ровно в тех условиях, в которых проект приходится
запускать без сети: локально, в закрытом контуре, на машине без выхода
на openaipublic. Там это не «мешает», а обнуляет поиск, поэтому P2 — с оговоркой:
если проект будут разворачивать офлайн, это P1.

## Как воспроизвести

    # без доступа к openaipublic
    .venv/Scripts/python.exe ingest_data.py        # падение на tiktoken
    # с заглушкой вместо словаря
    .venv/Scripts/python.exe tools/ingest_via_proxyapi.py   # «успех» + мусор
    # проверка
    .venv/Scripts/python.exe tools/qa_diag_alignment.py

## Предложение

1. В `database.py` создавать эмбеддинги с `check_embedding_ctx_length=False` —
   токенизация локально не нужна, модель делает её сама.
2. Проверка после сборки: 20 случайных чанков, косинус с пересчётом ≥ 0.99,
   иначе сборка неуспешна и индекс не публикуется.
3. В метаданные коллекции — имя модели, размерность, дата сборки, флаг режима.

## Закрытие (2026-10-30)

Две правки:

1. `database.py`: `OpenAIEmbeddings(..., check_embedding_ctx_length=False)` —
   в API уходит текст, а не локально посчитанные токены. Словарь BPE больше
   не нужен ни при индексации, ни при запросах.
2. `database.py`: после сборки индекса вызывается
   `_verify_embeddings_alignment()` — берёт 5 случайных чанков, пересчитывает
   их эмбеддинги и требует косинус ≥ 0.99. Если меньше — сборка падает
   с текстом «индекс собран с ошибкой: вектор не соответствует тексту».

Именно эта проверка поймала бы случай, на котором споткнулась приёмка:
«✅ загрузка завершена успешно», 4937 чанков, 1266 уникальных векторов.

Тесты: `tests/test_index_and_wording.py` — совпадение проходит, несовпадение
падает с понятным сообщением.
