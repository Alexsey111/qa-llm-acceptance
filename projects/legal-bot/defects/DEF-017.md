# DEF-017 · P2 · Вопрос не по теме уходит в уточнение «о каком договоре речь»

Проект: bot_for_legal_consultations
Дата: 2026-10-30
Источник находки: живой прогон (L-101) после исправления DEF-001
Статус: **исправлен**, проверено (см. «Закрытие»)

## Симптом

Вход: «как приготовить борщ»
Ответ бота:

    «❓ Уточните, пожалуйста:
     • О каком конкретно виде договора идет речь? (купля-продажа, аренда, подряд?)
     • Какая ситуация произошла?
     • Что именно вы хотите узнать?»

То есть на вопрос про суп бот спрашивает про вид договора.

## Причина

Две причины складываются:

1. Порога релевантности на практике нет (DEF-002): в production-режиме
   реранкер отключён и берутся просто top-5 найденных фрагментов.
2. Поиск возвращает случайные статьи (DEF-012), поэтому «борщ» находит статьи
   про договоры так же охотно, как «дарение».
3. QueryClarifier срабатывает на «≤3 слов + общее слово» и на «статьи из 3+
   частей ГК» — то есть на случайном наборе документов он срабатывает часто.

## Почему это дефект, а не «уточняющий вопрос — это хорошо»

Уточнение уместно, когда система поняла тему и просит деталей. Здесь она
не поняла тему вообще и вместо «это не по моей теме» перекладывает работу
на пользователя. Для бота, который должен отказываться от неюридических
вопросов, это ошибка поведения.

## Как воспроизвести

    .venv/Scripts/python.exe tools/qa_run_reference.py
    # L-101 → outcome=clarify вместо refuse

## Предложение

- Перед уточнением проверять, что найденные фрагменты вообще относятся к делу:
  минимальный score или проверка, что в вопросе есть юридическая лексика.
- Отдельный порог: если лучший score ниже X — отказ «не по моей теме»,
  без уточнений.
- В эталонный набор добавить 3–4 вопроса «не по теме» (погода, рецепт, спорт),
  чтобы регрессия ловилась сразу.

## Закрытие (2026-10-30)

Проверка темы вставлена в `retrieve_documents` перед гибридным поиском:

    relevance = self.check_topic_relevance(question)
    if not relevance["relevant"]:
        return [], ""          # дальше срабатывает штатный отказ «не нашёл»

Тем самым «нет темы» и «нет статей» сведены в один путь: если вопрос не про ГК,
до уточняющего вопроса дело не доходит, потому что документов нет вовсе.
Пустой набор документов уже обрабатывался в `get_answer` сообщением
«❌ Не нашел релевантных статей ГК РФ по вашему вопросу» — то есть новый отказ
не потребовал нового текста и не показывает пользователю внутренних причин.

Пороги и правило — в DEF-002 (они общие: одна проверка закрывает оба дефекта).

Проверка на живом движке:

    «как приготовить борщ» ................ ОТКАЗ  cos=0.34 cov=0.00
    «какое наказание за кражу» ............ ОТКАЗ  cos=0.51 cov=0.00
    «что решил Верховный суд по делу Иванова» ОТКАЗ  cos=0.40 cov=0.25
    «что такое договор дарения» ........... ОТВЕТ  cos=0.68 cov=1.00
    «что такое сервитут» .................. ОТВЕТ  cos=0.38 cov=1.00
    «как взыскать ущерб от кражи» ......... ОТВЕТ  cos=0.52 cov=0.33

Ложных отказов на своих вопросах: 0 из 20. Отбито чужих: 12 из 12
плюс вопрос из другой отрасли права, который по косинусу неотличим от своих.

Регрессия закрыта тестами `tests/test_topic_gate.py` (9 тестов), включая
случай «проверка упала — отвечаем как раньше» (fail-open), чтобы сбой Chroma
не превращался в отказ всем подряд.
