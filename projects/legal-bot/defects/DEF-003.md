# DEF-003 · P1 · Валидатор пропускает до двух выдуманных статей

Проект: bot_for_legal_consultations
Дата: 2026-10-30
Источник находки: чтение кода
Статус: **исправлено**

## Симптом

Валидатор проверяет, что упомянутые в ответе статьи есть в найденном контексте.
Но при небольшом расхождении ответ разрешается:

    # rag_engine.py:611-621
    hallucinated = mentioned_articles - context_articles
    if hallucinated:
        if len(hallucinated) <= 2 and len(mentioned_articles - hallucinated) > 0:
            log.warning("minor_hallucination_allowed", articles=list(hallucinated))
            # Разрешаем ответ с предупреждением
        else:
            return False, "Обнаружены ссылки на статьи вне контекста"

То есть ответ «по статье 454 … а также см. статью 812 и статью 999» уходит
пользователю: две выдуманные ссылки при одной верной считаются допустимыми.

## Почему это плохо именно здесь

Для юридического бота ссылка — это не украшение, а основание. Выдуманный номер
статьи пользователь предъявит юристу или в суде. Одна такая ссылка дороже
десяти неточных формулировок: доверие к системе рушится целиком.

## Как воспроизвести

1. Подготовить вопрос, где в контексте гарантированно одна статья
   (например, прямой запрос статьи 454).
2. Ожидаемо: любой номер вне контекста — отказ.
3. Фактически: до двух номеров проходят; в логах `minor_hallucination_allowed`
   без отказа.
4. Проверить на ответах, где LLM добавляет «см. также» — там и появляются
   выдуманные номера.

## Предложение

- Порог «до 2 допустимых» убрать: 0 или отказ.
- Если хочется мягкости — не пропускать ответ, а вырезать из него упоминания
  статей вне контекста и добавить пометку «ссылки удалены как непроверенные».
- Тест: ответ с одной верной и одной выдуманной ссылкой должен отклоняться.

## Закрытие (2026-10-30)

Убрано правило «до двух выдуманных статей можно, если рядом есть хоть одна
верная» — именно оно пропускало ответ с придуманной нормой.

Теперь ссылка вне контекста проверяется по самому кодексу (`get_article_by_number`):

    статьи нет в ГК ............. отказ, reason_code = "hallucination"
    статья есть, но не в выборке  пометка "cited_outside_context", ответ отдаётся

Если проверка не смогла обратиться к базе, модель не обвиняется в выдумке
(fail-open) — иначе сбой Chroma превращался бы в отказ всем подряд.

Тесты: `tests/test_hallucination_guard.py` — 3 штуки, включая «999 рядом
с верной 454 отклоняется» и «реальная ст. 15 вне контекста проходит с пометкой».
Чек-лист QA-20: было «принят» (ложный проход), стало «отклонён [hallucination]».
