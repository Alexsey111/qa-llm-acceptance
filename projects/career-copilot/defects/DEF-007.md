# DEF-007 · P2 · Тесты career-copilot не запускаются на чистой машине

Проект: career-copilot
Дата: 2026-10-30
Источник находки: прогон `pytest --collect-only` в .venv проекта
Статус: открыт

## Симптом

    .venv/Scripts/python.exe -m pytest --collect-only -q
    sqlalchemy.exc.OperationalError: (psycopg.errors.ConnectionTimeout)
    connection timeout expired

Сбор тестов падает ещё до запуска: 151 файл тестов не собирается, потому что
`tests/conftest.py:39-41` на импорте требует PostgreSQL:

    TEST_DATABASE_URL = os.getenv("TEST_DATABASE_URL",
        "postgresql+psycopg://career_user:career_pass@127.0.0.1:5433/career_copilot_test")

и сразу вызывает `ensure_test_database_exists(...)`.

## Почему это дефект

- В README нет строки «для тестов поднимите Postgres на порту 5433 и создайте
  базу»; человек, открывший репозиторий, получает таймаут и не понимает, что
  не так.
- 151 файл тестов выглядит как сильная сторона проекта, но проверить это
  утверждение нельзя без внешней инфраструктуры. В приёмке «тесты есть» и
  «тесты запускаются» — разные утверждения.
- Порт 5433 (не стандартный 5432) — значит, ожидается отдельный инстанс,
  который тоже нигде не описан.

## Как воспроизвести

1. Свежий клон, установка зависимостей по README.
2. `pytest --collect-only -q` без поднятого Postgres.
3. Фактически: ConnectionTimeout на этапе сбора.
4. Ожидаемо: либо тесты разделены на «юнит без БД» и «интеграционные с БД»,
   либо в README есть docker compose для тестовой базы, и `pytest` поднимает её сам.

## Предложение

- Разделить маркеры: `pytest -m "not db"` должен проходить без Postgres.
- Добавить в README раздел «Как прогнать тесты» с командой docker compose.
- В приёмке фиксировать отдельной строкой: сколько тестов запускается без
  внешних сервисов и сколько требует БД.
