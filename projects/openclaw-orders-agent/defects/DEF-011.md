# DEF-011 · P2 · openclaw-orders-agent: прогон сценариев не воспроизводится без локального сервиса

Проект: openclaw-orders-agent
Дата: 2026-10-30
Источник находки: попытка прогона `scripts/orders_ops.py test`
Статус: открыт

## Симптом

Проект устроен лучше большинства: есть сценарные тесты (5 кейсов в
`tests/messages.json`), команда прогона `python scripts/orders_ops.py test`
и файл результатов `tests/results.json`.

Файл результатов с прошлого прогона:

    "status": "passed", "passed": 5, "total": 5,
    "api": "http://127.0.0.1:8800"

Попытка повторить прогон сейчас не удалась: команда не отрабатывает, потому
что для неё нужен поднятый локальный сервис ядра на порту 8800. Ни в README,
ни в команде нет проверки «сервис недоступен — сделай вот это».

## Почему это дефект

- Артефакт «5 из 5 пройдено» существует, но проверить его нельзя: результат
  в репозитории — это отчёт о прошлом, а не доказательство.
- Нет ни одного сообщения о том, что тест не может стартовать без сервиса:
  человек запускает команду и получает непонятный код выхода.
- В приёмке разница принципиальная: «тесты проходят» и «есть файл, где написано,
  что они проходили» — разные утверждения.

## Как воспроизвести

    cd openclaw-orders-agent
    python scripts/orders_ops.py test
    # не стартует: нужен сервис на 127.0.0.1:8800

    # доказательство прошлого прогона:
    cat tests/results.json      # status passed, 5/5, api 127.0.0.1:8800

## Предложение

- В начале команды `test` проверять доступность сервиса и печатать
  «сервис не запущен, запустите ...» вместо непонятного кода выхода.
- Хранить в results.json дату и версию — иначе отчёт нечем привязать к коду.
- Описать в README последовательность: поднять ядро → прогнать тесты → где
  смотреть результат.
