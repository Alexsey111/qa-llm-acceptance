# Тест-план (сокращённый): openclaw-orders-agent — 10 проверок

Дата: 2026-11-02
Источник требований: `README.md` (таблица умений и раздел «Важно»), `AGENTS.md`
(роль и границы), `docs/RUNBOOK.md` (что должно быть поднято и автоматизация),
`data/settings.json` (адрес ядра).
Метод: проверка по требованию, а не по коду. Каждый пункт — утверждение из
документации, которое можно подтвердить или опровергнуть прогоном.
Провайдер ядра на прогоне: mock (`is_live=false`), деньги не тратились.

Приоритеты: P0 — врёт или опасно; P1 — работает неверно или не работает
автоматизация; P2 — мешает; P3 — косметика.

| ID | Проверка | Требование (откуда) | Как проверяется | Приоритет |
|----|----------|--------------------|-----------------|-----------|
| O-01 | Ядро доступно и агент честно называет провайдера | README: `health` → статус, провайдер, «тратит ли деньги»; AGENTS.md: перед `--analyze` смотреть `is_live` | `orders_ops.py health` | P0 |
| O-02 | Пять сквозных сценариев воспроизводятся сейчас, а не «когда-то» | README: `test` → 5 сценариев; DEF-011: файл результата без даты — не доказательство | `orders_ops.py test`, сверить дату в `tests/results.json` | P0 |
| O-03 | `ingest` идемпотентен: повторная заливка не создаёт дублей | README: «идемпотентно, без дублей» | два прогона `ingest` + подсчёт `external_id` в `/api/v1/orders` | P1 |
| O-04 | `triage --only-new` не пересчитывает уже разобранное | README: `--only-new` | два прогона подряд, сравнить `analyzed`/`processed` | P1 |
| O-05 | Решение по каждому из 5 заказов совпадает с ожидаемым (apply/review/skip + черновик) | README: основное умение; `tests/messages.json` | `order --external-id` по пяти ID | P0 |
| O-06 | Очередь ручной проверки показывает заказы, а не записи анализа | README: «что ждёт решения человека»; AGENTS.md: решение «на проверку» не отменяется, но и не дублируется | `queue` + сверка с числом заказов в `needs_review` | P1 |
| O-07 | Сводка содержит дату, провайдера и не затирается пустым прогоном | README: «Обе пишут в `reports/daily-summary.md`»; коммит «отчёт не затирается пустым» | `summary` при живом и при погашенном ядре, сверка md5 | P1 |
| O-08 | Неизвестный `external_id` даёт внятную ошибку и не роняет скрипт | AGENTS.md: вернуть `ok: false` и передать дословно | `order --external-id fl-9999-999` | P2 |
| O-09 | При недоступном ядре каждая команда объясняет причину, а не молчит | DEF-011, AGENTS.md: «если ядро недоступно, скрипт вернёт `ok: false`» | погасить ядро → `summary`, `test` | P1 |
| O-10 | Автоматизация по входу в систему реально формирует сводку | README: задача Windows «Orders Agent Summary (logon)»; RUNBOOK: запуск по входу вместо часов | `schtasks /Query /TN ...` (последний результат) + `reports/logon-summary.log` | P0 |
